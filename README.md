# max2tg-topic

Пересылает **один чат MAX** в **одну тему Telegram-группы**. Работает в одну сторону (MAX → Telegram), от личного аккаунта MAX, без платных сервисов. Построен на [PyMax](https://github.com/MaxApiTeam/PyMax) 2.5.0, поддерживает пароль 2FA.

Что пересылается:
- текст;
- фото и видео (несколько штук приходят альбомом);
- файлы, голосовые и стикеры;
- ответы (с цитатой) и пересланные сообщения;
- ссылки, контакты и служебные события чата.

Опросы и звонки приходят текстовой пометкой.

## Установка

### 1. Подготовьте Telegram
1. Создайте бота у @BotFather и возьмите токен.
2. Включите темы в группе и создайте нужную тему.
3. Добавьте бота в группу. Хватит прав участника на отправку сообщений. Если в группе ограничены права, сделайте бота админом.
4. Узнайте ID темы. Откройте ссылку на любое сообщение в теме: `https://t.me/c/<группа>/<ID_темы>/<сообщение>`. Для группы ID имеет вид `-100<группа>`.

### 2. Настройте проект
```bash
cp .env.example .env              # заполните MAX_PHONE, TG_*
mkdir -p data && sudo chown 1000:1000 data
docker compose build
```

### 3. Войдите в MAX (один раз)
```bash
docker compose run --rm max2tg login
```
Придёт SMS-код, введите его. Затем введите пароль 2FA: при вводе он не отображается. Сессия сохранится в `data/session.db`.

Новый аккаунт скрипт **не создаёт**. Если номер не зарегистрирован в MAX, вход просто завершится ошибкой.

### 4. Найдите ID чата
```bash
docker compose run --rm max2tg list-chats
```
Скопируйте ID в `MAX_CHAT_ID` в файле `.env`.

### 5. Запустите
```bash
docker compose up -d
docker compose logs -f
```

## С какого сообщения начинается пересылка

- **Первый запуск.** Начало задаёт `START_FROM`: `now`, `all`, `last:N` или дата `2026-11-01 14:30`. Старые сообщения приходят по порядку, рядом с именем отправителя стоит дата.
- **Все следующие запуски, перезапуски и обрывы связи.** Мост сам досылает всё, что пришло в MAX, пока он не работал. Отправная точка — последнее сообщение из `data/state.json`. Пока идёт догрузка, новые сообщения ждут своей очереди, поэтому порядок не нарушается.
- **Скорость.** Telegram пускает в одну группу около 20 сообщений в минуту, поэтому между отправками стоит пауза `TG_MIN_INTERVAL=3` с. 1000 сообщений истории займут около 50 минут, прогресс виден в логах.
- **Начать заново** с другим `START_FROM`: остановите контейнер, удалите `data/state.json` и запустите снова. Уже пересланные сообщения тогда придут повторно.

## Эксплуатация

- **Сессия MAX слетела.** Контейнер **не** пытается войти заново сам, иначе он слал бы SMS на каждом перезапуске. В логах появится «Сессия MAX недействительна». Тогда выполните `docker compose run --rm max2tg login` и `docker compose restart`.
- **Дубли.** ID уже пересланных сообщений хранятся в `data/state.json`, поэтому после переподключения дублей нет.
- **Большие файлы.** Bot API принимает файлы до 50 МБ. Вместо файлов крупнее приходит пометка.
- **Обновление PyMax.** Версия закреплена в `requirements.txt`. Меняйте её, только если MAX что-то сломал, и сначала читайте changelog.
- **`data/session.db` даёт полный доступ к аккаунту MAX.** Храните его так же бережно, как пароль.

## Риски

Это неофициальный клиент: PyMax притворяется Android-приложением MAX. Аккаунт теоретически могут ограничить. Мост ничего не отправляет в чаты MAX, только принимает сообщения. В списке устройств MAX он будет виден как отдельное Android-устройство.

## Разработка

```bash
uv sync                 # окружение + ruff
uv run ruff check --fix # линтер
uv run ruff format      # форматтер
```

Зависимости приложения дублируются в `requirements.txt` (из него ставит Dockerfile) — держите их в синхроне с `pyproject.toml`.
